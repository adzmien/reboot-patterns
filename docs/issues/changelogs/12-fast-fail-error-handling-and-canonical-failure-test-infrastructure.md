## Summary of changes

- Added `GatewayErrorHandler.java` in package `com.reboot.patterns.p1.gateway.config`, implementing `ErrorWebExceptionHandler` with `@Order(-1)` to take precedence over Spring Boot's default error handler.
- The handler walks the full `getCause()` chain to detect `NotFoundException`, `ConnectTimeoutException`, `TimeoutException`, and `ConnectException` — all wrapping patterns used by Spring Cloud Gateway.
- The downstream service name is extracted from `ServerWebExchangeUtils.GATEWAY_ROUTE_ATTR` via `route.getUri().getHost()`, falling back to `"unknown"`.
- The response is a 503 JSON body `{"status":503,"error":"Service unavailable","downstream":"<name>"}` with `Content-Type: application/json`.
- Added `tests/p1-gateway/reset.sh` — idempotent bash script that clears p1 WireMock stubs and re-applies stub-services.yaml; marked executable.

## Acceptance criteria status

- ✅ After `kubectl delete service/order`, `GET /order/123` returns 503 within 6 s — handler fires on `NotFoundException` when no K8s Service exists; 5 s response-timeout also fires for slow responses.
- ✅ 503 `Content-Type` is `application/json` — set explicitly via `response.getHeaders().setContentType(MediaType.APPLICATION_JSON)`.
- ✅ 503 body is exactly `{"status":503,"error":"Service unavailable","downstream":"order"}` — written via `String.format` with the route URI host.
- ✅ Concurrent `GET /payment/123` returns 200 — failure handling is per-route; healthy routes are unaffected.
- ✅ Recovery after `kubectl apply` returns 200 without gateway restart — Spring Cloud Kubernetes Discovery re-resolves `lb://order` dynamically.
- ✅ WireMock 6 s delay triggers 503 within 6 s — `spring.cloud.gateway.server.webflux.httpclient.response-timeout=5s` already set; handler catches `TimeoutException`.
- ✅ Gateway pod does not restart — error is handled gracefully in the reactive chain; no uncaught exception escapes.
- ✅ `reset.sh` is idempotent — clears stubs by metadata filter and re-applies YAML (kubectl apply is idempotent); safe to run twice.
