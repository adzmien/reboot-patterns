## What to build

The gateway returns a machine-readable 503 JSON response within the 5-second timeout when a downstream service is unreachable — never a hanging request, never an HTML Whitelabel Error page. This issue is the **definition-of-done gate** for p1-gateway: it contains the canonical-failure scenario and creates the `reset.sh` that all subsequent p1 bash tests depend on.

**`GatewayErrorHandler.java`** — implements `ErrorWebExceptionHandler` with `@Order(-1)` (highest precedence, overrides Spring Boot's default `DefaultErrorWebExceptionHandler`):
- Handles `ServiceUnavailableException`, `io.netty.channel.ConnectTimeoutException`, and `java.util.concurrent.TimeoutException` (inspect `getCause()` chains — Spring Cloud Gateway wraps exceptions in `ResponseStatusException`)
- Extracts the downstream service name from the `ServerWebExchange` route attribute
- Writes JSON body `{"status":503,"error":"Service unavailable","downstream":"<name>"}` and sets `Content-Type: application/json`

**`tests/p1-gateway/reset.sh`** — idempotent reset script (must be sourced at the start of every p1 test script):
```bash
#!/usr/bin/env bash
# reset.sh — idempotent reset for p1-gateway tests.
# Must be sourced at the start of every p1 test script.
NODE_IP="100.66.8.44"

echo "p1-gateway reset: clearing WireMock stubs for pattern p1"
curl -sf "http://${NODE_IP}:30080/__admin/mappings" \
  | jq -r '.mappings[] | select(.metadata.pattern == "p1") | .id' \
  | while read -r id; do
      curl -sf -X DELETE "http://${NODE_IP}:30080/__admin/mappings/${id}" > /dev/null
    done

echo "p1-gateway reset: re-applying stub K8s Services"
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
kubectl apply -f "${SCRIPT_DIR}/../../patterns/p1-gateway/k8s/stub-services.yaml" \
  || { echo "ERROR: failed to apply stub-services.yaml"; exit 1; }

echo "p1-gateway reset complete"
```

The canonical-failure scenario script (`tests/p1-gateway/routing-and-failure.sh`) is generated by `/generate-tests` from the commit diff — do not hand-author it here.

## Acceptance Criteria

- [ ] After `kubectl delete service/order -n reboot-patterns`, `GET /order/123` returns HTTP 503 within 6 seconds total elapsed time
- [ ] The 503 response `Content-Type` header is `application/json`
- [ ] The 503 response body is exactly `{"status":503,"error":"Service unavailable","downstream":"order"}`
- [ ] Concurrent `GET /payment/123` (payment stub Service intact) returns HTTP 200 — failure is isolated to the deleted route
- [ ] After `kubectl apply -f patterns/p1-gateway/k8s/stub-services.yaml`, `GET /order/123` returns HTTP 200 again without restarting the gateway
- [ ] With WireMock stub configured to delay 6 seconds (`fixedDelayMilliseconds: 6000`) for `GET /order/**`, `GET /order/123` returns HTTP 503 within 6 seconds (timeout fires, not a hang)
- [ ] Gateway pod does not restart or crash during any failure injection
- [ ] `source ./tests/p1-gateway/reset.sh` is idempotent — safe to run twice in succession without errors
